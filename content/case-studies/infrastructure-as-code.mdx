## Module design

I built a small set of composable modules, one per network building block, and a Terragrunt layout that keeps each environment to a few lines of input.

```hcl
module "spoke_vpc" {
  source          = "git::https://git.example.com/tf/network//spoke-vpc?ref=v2.4.0"
  name            = "payments-prod"
  cidr            = "10.42.0.0/16"
  azs             = ["ap-southeast-1a", "ap-southeast-1b", "ap-southeast-1c"]
  transit_gateway = dependency.hub.outputs.tgw_id
  egress          = "centralised"
}
```

### Importing what already existed

Rather than recreating live networks, we imported existing resources in batches, compared plans to zero diff, and only then handed each environment over to the pipeline.

## Guardrails

### Policy as code

OPA policies run against every plan: no public subnets without an approved exception, no `0.0.0.0/0` ingress, mandatory tags, and CIDRs that must come from the IPAM allocation.

| Check | Tool | Blocks merge |
|-------|------|--------------|
| Formatting and validation | terraform fmt / validate | Yes |
| Security misconfigurations | Checkov | Yes |
| Organisation policy | OPA / Conftest | Yes |
| Cost estimate | Infracost | No (comment only) |

### Drift detection

A nightly job runs `terraform plan` for every environment and opens an issue when it finds differences, so console changes are caught within a day.

## Key decisions and trade-offs

1. **Terragrunt over workspaces**: Explicit directories per environment made plans easier to review and state files smaller and safer.

2. **Versioned modules**: Environments pin module versions, so a module change never silently alters production. Upgrades are their own reviewed pull requests.

3. **Plan output in pull requests**: Reviewers see a summarised plan as a comment, which made security and network reviewers comfortable approving changes without reading HCL.
