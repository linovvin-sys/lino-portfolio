## Architecture

Every cluster is managed by Argo CD from a single Git repository. Application teams own a folder with a Helm values file; the platform team owns the base charts, network policies and cluster add-ons.

### Networking with Cilium

Cilium replaced kube-proxy and gave us identity-aware network policy, so rules are written in terms of services, not IP addresses that change with every pod.

```yaml
apiVersion: cilium.io/v2
kind: CiliumNetworkPolicy
metadata:
  name: payments-api
spec:
  endpointSelector:
    matchLabels: { app: payments-api }
  ingress:
    - fromEndpoints:
        - matchLabels: { app: checkout-web }
      toPorts:
        - ports: [{ port: "8443", protocol: TCP }]
```

## Progressive delivery

Deployments use rolling updates with readiness gates, and critical services use canaries that watch error rate and latency before promoting.

| Stage | Traffic | Promotion check |
|-------|---------|-----------------|
| Canary | 5% | Error rate and p95 latency within SLO for 5 min |
| Partial | 50% | Same checks for 10 min |
| Full | 100% | Automatic |

## Key decisions and trade-offs

1. **GitOps over pipeline pushes**: CI builds and tests images; Argo CD is the only thing that changes the cluster. That gave us a complete audit trail and made drift impossible.

2. **Vault with the External Secrets Operator**: Secrets stay in Vault and are synced into namespaces at runtime, with per-team access policies.

3. **Paved road, not a gate**: A service template with CI, Helm chart, dashboards and alerts built in meant the easiest way to ship was also the right way.
