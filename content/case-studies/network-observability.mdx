## Architecture

Devices that support it stream interface, BGP and optics data over gNMI every 10 seconds. Telegraf collects the streams and exposes them to Prometheus, while older devices stay on SNMP through the same collectors, so dashboards don't care which protocol a device speaks.

```yaml
[[inputs.gnmi]]
  addresses = ["spine-01:57400", "spine-02:57400"]
  encoding = "proto"
  [[inputs.gnmi.subscription]]
    name = "ifcounters"
    origin = "openconfig"
    path = "/interfaces/interface/state/counters"
    subscription_mode = "sample"
    sample_interval = "10s"
```

## From thresholds to SLOs

Static thresholds ("interface over 80%") paged people for things that didn't hurt anyone. We defined service-level objectives for what users actually feel, then alerted on how quickly each error budget was being burned.

| Service | SLO | Alert |
|---------|-----|-------|
| Internet edge availability | 99.95% | Fast burn (2% budget in 1h) pages |
| Data center fabric packet loss | < 0.01% | Slow burn (5% in 6h) opens ticket |
| Branch WAN latency | p95 < 60ms | Slow burn opens ticket |

### Dashboards that answer questions

Each dashboard starts from a question on-call engineers actually ask: *Is it the network?* *Which link?* *Since when?* Drill-downs go from service, to site, to device, to interface in three clicks.

## Key decisions and trade-offs

1. **Prometheus over a commercial NMS**: Open formats and PromQL let us build SLO alerts that the vendor tools couldn't express, at a fraction of the cost.

2. **Keeping SNMP for legacy devices**: A hybrid collector meant we didn't have to wait for hardware refreshes to get one consistent view.

3. **Logs next to metrics**: Syslog in Loki, linked from every Grafana panel, turned "check the logs" from a separate hunt into one click.
